Save received files to the gallery: DICOM, JPG, BMP, MP4, AVI, PDF

saveFrame() only ever touched the gallery for .jpg/.jpeg/.png. Everything else
the P50 offers on its QR Export screen -- BMP stills, MP4/AVI cine loops, the
PDF report, and DICOM itself -- was written to the study folder and then never
appeared in Photos, so a study "arrived" and could not be found.

fileKinds.ts identifies a file from its magic bytes rather than its name. The
P50 mislabels its own exports (a cine loop arrives as .jpg), so a name-based
decision both misfiles and silently drops files. Every format has a fixed
signature at a fixed offset, and the test pins each offset so no two can
collide. A transfer still in flight has no readable signature, so it falls back
to the name and says so, and the content takes over once the file arrives.

gallerySaver.ts routes by format:
  jpg/png/bmp -> gallery photo
  mp4        -> gallery video
  dicom      -> decoded to PNG, then gallery (first frame only, so a 200-frame
                cine does not bury every other study under hundreds of entries;
                all frames stay in the study folder)
  avi, pdf   -> study folder only, with the reason reported

AVI and PDF stay out on purpose: Android's MediaStore has no row type for
either and iOS's camera roll has no PDF type, so an entry would open to an
error, which is worse than no entry. A refused gallery permission never aborts
the save, because the file is already on disk by then.
